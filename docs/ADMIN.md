## Встановлення

Потрібні Python 3.10+ і токен бота від [@BotFather](https://t.me/BotFather).

```bash
# окремий користувач без домашньої теки та входу в систему
sudo useradd --system --no-create-home --shell /usr/sbin/nologin hoe

sudo git clone https://github.com/DraKuLa21-a42/HoeShutdownNotifier_v2.git /opt/HoeShutdownNotifier
sudo chown -R hoe:hoe /opt/HoeShutdownNotifier
cd /opt/HoeShutdownNotifier

sudo -u hoe python3 -m venv venv
sudo -u hoe venv/bin/pip install --no-cache-dir -r requirements.txt
sudo -u hoe cp .env.example .env
sudo -u hoe venv/bin/python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
sudo -u hoe nano .env            # BOT_TOKEN, ADMIN_IDS — обов'язково; SECRET_KEY — ключ із команди вище
sudo -u hoe mkdir -p data
sudo chmod 600 .env

sudo cp deploy/hoe-notifier.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now hoe-notifier
journalctl -u hoe-notifier -f
```

Відкрийте бота в Telegram і надішліть `/add`.

## Оновлення

```bash
cd /opt/HoeShutdownNotifier
sudo -u hoe git pull
sudo -u hoe venv/bin/pip install --no-cache-dir -r requirements.txt
sudo systemctl restart hoe-notifier
```

База мігрує автоматично під час запуску. Перегляньте `.env.example` — у новій версії можуть з'явитися нові змінні.

> **Оновлення з версії без `SECRET_KEY`.** Згенеруйте ключ (див. [нижче](#шифрування-секретів-secret_key)) і додайте
> в `.env`. Під час наступного запуску наявні токени Slack-ботів буде зашифровано автоматично. Якщо ви вже вказували
> `CABINET_SECRET_KEY`, він працює як `SECRET_KEY` — просто перейменуйте змінну.

## Резервна копія

Усі підписки, стан адрес і акаунти лежать в одному файлі `data/hoe.sqlite3`. Узгоджена копія під час роботи сервісу:

```bash
sqlite3 data/hoe.sqlite3 ".backup '/шлях/hoe-backup.sqlite3'"
```

Зберігайте копію бази **окремо** від `.env`: секрети в базі зашифровані ключем із `.env`, і разом вони дають доступ
до паролів користувачів.

## Налаштування

Усе задається в `.env` (приклад із коментарями — `.env.example`). Параметри з позначкою 🤖 можна змінювати й у
боті — у [меню налаштувань](#меню-налаштувань-у-боті-settings); значення з бота мають пріоритет над `.env`.

| Змінна | За замовч. | Опис |
|---|---|---|
| `BOT_TOKEN` | — | Токен від @BotFather. Формат `bot123:ABC` зі старих версій теж працює |
| `ADMIN_IDS` | — | Telegram ID адміністраторів через кому: попередження про збої, `/admin`, `/stats`, керування в будь-якому чаті |
| `ALLOWED_CHAT_IDS` 🤖 | порожньо | Обмежити бота списком чатів/користувачів. Порожньо — бот відкритий для всіх |
| `MAX_ADDRESSES_PER_CHAT` 🤖 | `5` | Скільки адрес може мати один чат чи канал |
| `POLL_INTERVAL` 🤖 | `900` | Секунд між перевірками сайту (мінімум 60) |
| `REQUEST_TIMEOUT` 🤖 | `15` | Таймаут запиту до сайту, с |
| `RETRIES` / `RETRY_DELAY` 🤖 | `3` / `5` | Спроби на запит і початкова пауза між ними (далі подвоюється) |
| `CONCURRENCY` 🤖 | `3` | Скільки адрес опитувати одночасно |
| `DEFAULT_SILENT` 🤖 | `true` | Нові адреси — повідомлення без звуку |
| `DEFAULT_GRAPHS` 🤖 | `false` | Нові адреси — слати картинку з графіком |
| `SECRET_KEY` | порожньо | Ключ Fernet для шифрування секретів у базі. **Дуже рекомендовано** ([докладніше](#шифрування-секретів-secret_key)) |
| `CABINET_ENABLED` 🤖 | `true` | Інтеграція з особистим кабінетом (працює лише із `SECRET_KEY`) |
| `CABINET_SYNC_INTERVAL` 🤖 | `21600` | Секунд між оновленнями черг із кабінету (мінімум 900) |
| `CABINET_BASE_URL` | `https://cabinet.hoe.com.ua` | Адреса особистого кабінету |
| `SLACK_TOKEN` 🤖 | — | Необов'язково: спільний токен Slack лише для записів з `addresses.toml`. Користувачі підключають своїх ботів через `/slack` |
| `DB_PATH` / `ADDRESSES_FILE` | `data/hoe.sqlite3` / `addresses.toml` | Розташування бази та файлу адрес |
| `HOE_BASE_URL` | `https://hoe.com.ua` | Адреса сайту |
| `LOG_LEVEL` 🤖 | `INFO` | Рівень журналу |

## Меню налаштувань у боті (/settings)

Більшість параметрів сервісу можна змінювати прямо в Telegram, без редагування `.env` і перезапуску.
Меню доступне лише користувачам з `ADMIN_IDS`, лише в приватному чаті, і захищене **окремим паролем** — на випадок,
якщо хтось отримає доступ до Telegram-акаунта адміністратора.

**Як відкрити:** `/settings` або `/admin` → «⚙️ Налаштування (з паролем)».

- **Перший вхід** — бот попросить створити пароль (щонайменше 8 символів, двічі). Пароль спільний для всіх
  адміністраторів; у базі зберігається лише його хеш (scrypt).
- **Сесія** закривається після 15 хвилин без дій або кнопкою «🔒 Вийти». Після перезапуску сервісу всі сесії закриті.
- **Захист від підбору:** після 5 невдалих спроб вхід блокується на 15 хвилин, а інші адміністратори отримують
  повідомлення.
- Повідомлення з паролями й токенами бот одразу видаляє з чату.
- **Змінити пароль** — кнопка «🔑 Змінити пароль» у меню. **Забули пароль** — скиньте його на сервері, і наступний
  `/settings` запропонує створити новий:
  ```bash
  sudo -u hoe venv/bin/python -m hoe_notifier reset-settings-password
  sudo systemctl restart hoe-notifier
  ```

**Що можна змінити:**

| Група | Параметри |
|---|---|
| Поведінка | інтервал опитування, ліміт адрес на чат, типові «без звуку» і «графік» для нових адрес |
| Доступ | дозволені чати (`ALLOWED_CHAT_IDS`) |
| Особистий кабінет | увімкнення інтеграції, інтервал оновлення черг |
| Технічні | таймаут, кількість спроб і пауза між ними, кількість одночасних запитів, рівень журналу |
| Інтеграції | спільний токен Slack (`SLACK_TOKEN`; зберігається зашифрованим, потрібен `SECRET_KEY`) |

Біля кожного значення видно, звідки воно: 🤖 — змінено в боті, 📄 — з `.env`, ▫️ — за замовчуванням. Кнопка
«↩ Скинути до .env» прибирає значення з бота. Зміни діють одразу (інтервал опитування — з наступного циклу), про кожну
зміну отримують повідомлення інші адміністратори, а «📜 Журнал змін» показує останні зміни: хто, коли, було → стало.

**Лише в `.env`** лишаються `BOT_TOKEN`, `SECRET_KEY`, `ADMIN_IDS`, `DB_PATH` — без них бот не запуститься або
вони втратили б сенс (ключ шифрування не можна зберігати в базі, яку він захищає), — а також `HOE_BASE_URL`,
`CABINET_BASE_URL`, `ADDRESSES_FILE`, які майже ніколи не змінюються.

> Спільний `SLACK_TOKEN`, змінений у боті, діє для нових повідомлень одразу, але список записів `addresses.toml` зі
> Slack перечитується лише під час запуску.

## Шифрування секретів (SECRET_KEY)

У базі зберігаються чужі секрети: токени Slack-ботів, які підключають користувачі, і паролі та токени від
особистого кабінету. З `SECRET_KEY` вони шифруються (Fernet), тож сама база (резервна копія, випадково скопійований
файл) нічого не дає без ключа.

```bash
venv/bin/python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
# у .env: SECRET_KEY=<ключ>
```

- **Без ключа** токени Slack зберігаються відкритим текстом (у журналі при запуску буде попередження), а інтеграція з
  кабінетом вимкнена. Коли ключ з'явиться, відкриті токени зашифруються під час наступного запуску.
- **Не губіть і не змінюйте ключ.** Без нього збережене не розшифрується:
  - Slack-боти перестануть надсилати повідомлення (у журналі — «токен не розшифровується»; підписки **не**
    видаляються). Користувачам доведеться видалити й заново підключити бота в `/slack`.
  - Для кабінету бот повідомить власникам, що «пароль не підходить», і попросить ввести його знову в `/cabinet`.
- Той, хто має доступ і до бази, і до `.env`, може розшифрувати секрети. Тому `.env` — з правами `600`, а копії бази
  тримайте окремо від нього.

## Особистий кабінет

Користувачі можуть дати боту логін і пароль від [cabinet.hoe.com.ua](https://cabinet.hoe.com.ua), і черга адреси
береться з договору та оновлюється автоматично ([як це виглядає для користувача](USER.md#черга-з-особистого-кабінету)).
Вмикається разом із `SECRET_KEY`; вимкнути окремо — `CABINET_ENABLED=false`.

- Черги оновлюються на початку циклу опитування, не частіше ніж раз на `CABINET_SYNC_INTERVAL` (типово 6 год):
  один запит на договір. Токен кабінету діє добу і зберігається в базі, тож вхід — приблизно раз на добу на акаунт.
- Нову чергу застосовано одразу; чат отримує повідомлення «Змінилась черга відключень» з поточним станом для нової черги.
- Якщо пароль перестав підходити, власник **один раз** отримує повідомлення, а акаунт більше не пробується (щоб не
  заблокувати його невірним паролем), доки користувач не введе новий пароль. Остання відома черга лишається.
- Якщо кабінет недоступний, помилка видна в `/cabinet` у користувача; черга не змінюється.
- Якщо в кабінеті з'являться відключення за договором (поле `shutdowns`), вони пишуться в журнал (`Кабінет …: shutdowns = …`)
  — це знадобиться, щоб підключити їх як джерело даних.
- `/admin` → «📊 Статистика» показує, скільки адрес мають чергу з кабінету і скільки акаунтів підключено.

## Панель адміністратора

Команда `/admin` (лише для `ADMIN_IDS` і лише в приватному чаті з ботом) відкриває панель із кнопками:

| Кнопка | Що робить |
|---|---|
| 📊 Статистика | Чатів, підписок, адрес, чатів із графіком, адрес із чергою (і з кабінету), час останнього циклу |
| 👥 Усі підписки | Усі підписки за чатами: адреса, черга (🔐 — з кабінету), прапорці (графік, звук, 🔒 з файлу), назва чату |
| 🔄 Опитати зараз | Запускає повний цикл опитування, не чекаючи наступного за розкладом |
| 📋 Показати текстовий графік | Показує поточний текстовий графік **лише вам** |
| 🖼 Показати картинку-графік | Показує поточну картинку **лише вам** |
| 📤 Розіслати текстовий графік | Надсилає текст усім чатам, що ввімкнули «Графік» |
| 📤 Розіслати картинку-графік | Те саме для картинки |
| ⚙️ Налаштування (з паролем) | [Меню налаштувань](#меню-налаштувань-у-боті-settings) |

Розсилка робиться **з підтвердженням**: бот показує попередній перегляд і кількість чатів. Ручна розсилка позначає
графік як надісланий, тому автоматично він вдруге не піде.

Інші команди адміністратора:

| Команда | Що робить |
|---|---|
| `/subs [сторінка]` | Лише в приваті: усі підписки всіх чатів (по 10 на сторінку, кнопки ◀ ▶) |
| `/stats` | Чатів, підписок, адрес, час останнього циклу |
| `/settings` | Лише в приваті, з паролем: [меню налаштувань](#меню-налаштувань-у-боті-settings) |

Адміністратори також можуть керувати адресами в будь-якому чаті й отримують попередження, коли сайт кілька циклів
поспіль недоступний.

## Адреси з файлу (`addresses.toml`)

Адреси можна задавати файлом замість бота — див. `addresses.example.toml`. Записи синхронізуються в базу при старті
сервісу, у `/list` позначені 🔒 і не змінюються з бота. Для Slack тут використовується спільний `SLACK_TOKEN`.

```toml
[[address]]
name = "Дім"
street_id = "123456"
house = "12"
send_to = "tg"                 # tg | slack
target = "-1001553812345"      # chat_id або ID каналу
graphs = true
queue = "1.1"                  # необов'язково: лише відключення цієї черги
```

## Як це працює

```
┌──────────┐  /add, /list …   ┌─────────┐        ┌─────────────┐
│ Telegram │ ───────────────► │   bot   │ ─────► │   SQLite    │  підписки, стан адрес, акаунти
└──────────┘                  └─────────┘        └──────▲──────┘
      ▲                                                 │
      │ повідомлення         ┌───────────────┐          │
      └───────────────────── │    monitor    │ ◄────────┘
                             │ кожні N секунд│ ───► POST hoe.com.ua/shutdown-events
                             └───────────────┘       (один запит на унікальну адресу)
                                     │
                                     └──────────► cabinet.hoe.com.ua (черги, раз на кілька годин)
```

1. Монітор оновлює черги з особистого кабінету (якщо настав час).
2. Збирає **унікальні** адреси з усіх підписок і опитує кожну одним запитом (не більше `CONCURRENCY` одночасно).
3. Порівнює результат зі збереженим станом і розсилає зміни всім підписникам адреси (кожному — з урахуванням його
   черги). Стан зберігається **до** розсилки, тому збій доставки не призводить до повторів.
4. Окремо перевіряє сторінку графіків (за один запит — і картинку, і текст) і надсилає новий графік тим, хто ввімкнув
   «Графік».

Бот користується тими самими запитами, що й форма на hoe.com.ua:

| Крок | Запит до сайту |
|---|---|
| Населений пункт | `GET /settlements/?term=…` |
| Вулиця | `GET /streets/{id населеного пункту}?term=…` |
| Будинок | `GET /houses/{streetId}` |
| Відключення | `POST /shutdown-events` (`streetId`, `house`) |
| Графік | `GET /page/pogodinni-vidkljuchennja` |

Особистий кабінет: `POST /Token` (вхід, bearer-токен на добу), `GET /api/household-consumers/cabinet/get-by-user`
(договори), `GET /api/household-consumers/technical-data/get-oms-data/{cabinetId}` (черга).

### Надійність і навантаження на сайт

- Ручні `/check` і додавання адреси не б'ють у сайт частіше, ніж раз на 60 с на адресу (інакше відповідь береться з кешу).
- Якщо сайт не відповів на 3 адреси поспіль, цикл переривається і повторюється наступного разу — без хвилин марних ретраїв.
- Невідомий формат відповіді (змінилась верстка) не псує збережений стан і не спамить підписників; адмін отримує
  одне попередження, а після відновлення — одне «знову працює».
- Довгий текст відключень обрізається до ліміту Telegram.
- Групу перетворили на супергрупу — підписки переносяться на новий `chat_id` автоматично.
- Бота вилучили з чату або користувач його заблокував — підписки цього чату видаляються одразу.

## Поширені питання

<details>
<summary><b>Як дізнатись свій Telegram ID для <code>ADMIN_IDS</code>?</b></summary>

Напишіть [@userinfobot](https://t.me/userinfobot) — він відповість вашим числовим ID.
</details>

<details>
<summary><b>«Не вдалося отримати дані з сайту»</b></summary>

Сайт тимчасово недоступний або змінив верстку. Подивіться журнал: `journalctl -u hoe-notifier -n 100`. Якщо проблема
триватиме кілька циклів, адмін отримає попередження в Telegram.
</details>

<details>
<summary><b>Бот не відповідає в групі</b></summary>

У групі бот за замовчуванням бачить лише команди й відповіді на свої повідомлення (privacy mode). Діалог `/add` це
враховує. Альтернатива — вимкнути privacy mode у @BotFather (`/mybots` → Bot Settings → Group Privacy).
</details>

<details>
<summary><b>Як перенести адреси зі старої версії (1.x)?</b></summary>

```bash
venv/bin/python -m hoe_notifier import-legacy home
```
Команда лише **друкує** готові фрагменти для `.env` і `addresses.toml` на основі старого файлу конфігурації
(нічого не записує). Старий cron-рядок видаліть.
</details>

## Безпека

- `.env` і `addresses.toml` у `.gitignore` — токени не потрапляють у git. Тримайте `.env` з правами `600`.
- Задайте `SECRET_KEY`: без нього токени Slack-ботів користувачів лежать у базі відкритим текстом. Не комітьте ключ і
  не зберігайте його поруч із резервними копіями бази.
- Сервіс працює від окремого системного користувача (`deploy/hoe-notifier.service`); обмежте доступ до папки `data/`.
- Секрети (токени, паролі) не пишуться в журнал; повідомлення з ними бот видаляє з чату.
- Якщо токен бота колись потрапляв у git-історію — відкличте його через @BotFather (`/revoke`).
- Для приватного використання задайте `ALLOWED_CHAT_IDS` (або «Дозволені чати» в `/settings`), щоб бот відповідав
  лише вашим чатам.
- Пароль меню `/settings` не повторюйте з іншими сервісами; журнал змін і сповіщення іншим адміністраторам
  допоможуть помітити чужі дії.

## Для розробників

```
hoe_notifier/
├── __main__.py        точка входу, команда import-legacy
├── bot.py             Telegram-бот (діалоги, команди, кнопки)
├── monitor.py         опитування сайту, порівняння стану, розсилка, оновлення черг із кабінету
├── hoe.py             клієнт hoe.com.ua, парсери відповідей, підбір будинку
├── cabinet.py         особистий кабінет: вхід, токен, черга з договору
├── crypto.py          шифрування секретів у базі (SECRET_KEY)
├── runtime.py         налаштування з меню /settings поверх .env, пароль меню
├── db.py              SQLite: підписки, стан адрес, Slack-боти, акаунти кабінету
├── queues.py          черги ГПВ: розпізнавання та фільтрація текстів
├── sinks.py           доставка: Telegram, Slack
├── addresses_file.py  читання addresses.toml
└── config.py          налаштування з .env
tests/                 pytest (парсер, БД, розсилка, HTTP-клієнти, кабінет, шифрування, налаштування, діалоги бота)
  └─ fixtures/        збережена справжня сторінка графіка для тестів парсера
deploy/                приклад systemd-юніта
docs/                  інструкції для користувачів і адміністраторів
```

```bash
pip install -r requirements-dev.txt
pytest
```

Тести не потребують ні мережі, ні токена: сайти й Telegram підмінюються, повні діалоги бота проганяються на
підставному сеансі. На GitHub вони запускаються автоматично на Python 3.10–3.13.
